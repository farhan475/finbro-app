# Changelog

## 1.0.0+1 — first public release (GitHub `v1.0.0`, 7 Okt 2026)
Everything below, up to the release policy, ships in this build. See `SUMMARY.md` for the full feature list.

- New (widget, owner decision: grows with its size instead of a setting): resized taller, the widget adds the change line ("↑ +37% dari bulan lalu") and Income | Expense (medium), then Available to Spend, the highest-usage budget ("Family · 100% · Limit reached", toned) and the next schedule ("Internet · H-7 · -Rp 385.000", red when overdue) (large). The tier follows each widget's current height (`FinBroWidgetProvider.tierFor`); masked snapshots carry no details, so a masked widget never shows them. Sections open their screen: balance / Available to Spend → Home, Income/Expense → Analitik, budget → Budget, schedule → Transaksi Berulang (`WidgetTarget`; cold start and running app).
- Fixed (widget): `WidgetSync` now also recomputes after writes to `budgets`, `categories`, `goals`, `recurring_rules` and `recurring_instances`, which the taller rows read; before, a new schedule or budget only reached the widget on the next app resume or 30-min update. Regression in `test/core/widget/widget_background_test.dart`.
- Changed (widget, owner request): the home-screen widget is now a 4×2 card like the Home "Total Balance" card — label, update time, amount and the month's balance line (drawn in Kotlin, `WidgetChart.kt`, from `FinanceService.monthBalancePath`, the same path as the Home sparkline); negative totals in red; light/dark from the system; masked states show `Rp ••••••` without a chart. New "Widget layar utama" tile in Pengaturan pins it (Android 8+) and a Bantuan entry explains it.
- Fixed (widget): system updates (placement, 30-min period) started a cached Flutter engine straight from the broadcast receiver, whose process could be killed before Dart rendered, leaving "Memuat…" or an old amount. They now run as WorkManager work (`WidgetRefreshWorker`), which waits for Dart's `done` and destroys the engine. `WidgetCompute.kt` removed.
- Fixed: Impor Mutasi Bank with two or more active accounts threw `StateError` (both file buttons used `accounts.single`) and ignored the chosen account. The dropdown choice is now the import target and the buttons stay disabled until an account is picked.
- Fixed: kurs typed with an Indonesian thousands separator (`16.250`) was saved as 16,25. Kurs fields in Kurs Mata Uang and the account form parse with `parseRate` ('.' thousands, ',' decimal; a lone '.' not followed by a 3-digit group stays a decimal mark) and display with `formatRateInput` (`16.250`, `105,25`).
- Fixed: Home "Akun" chips formatted non-IDR balances as rupiah (`$100,00` showed as `Rp 10.000`). Available to Spend is now hidden by the Home eye toggle too.
- UI: Kurs Mata Uang redesigned (info card; per-currency row with symbol, code, name, "Diubah <tanggal>" and a right-aligned rupiah field; save pinned at the bottom; only changed rates are written so the date reflects the real edit). Account form: currency dropdown before kurs and opening balance, live ≈Rp preview. Notifikasi and Log aplikasi tidied. Navbar labels capped at 1.3× and shrink to fit (overflowed at 200% font); Available to Spend and kurs rows stack at large font scales.
- UI text: folder backup, recurring auto-confirm and Bantuan mention the ~6 h background run, not only app open.
- Removed: unreachable `/settings` route and `SettingsScreen` (settings are in Lainnya → Pengaturan).
- New: scanned (image-only) PDF bank statements are read with on-device OCR on Android: each page is rendered with pdfrx (~216 dpi, longest side ≤ 3000 px, one temp image at a time), recognized by ML Kit, laid out into lines and parsed by the statement line parser; sideways pages are re-rendered upright. Max 30 pages, progress "halaman X dari N" with Batal, review labelled "PDF scan (OCR)" with a check-the-numbers warning. Off Android, or when no text is found, a clear rejection.
- Fixed: statement timestamps read by OCR as "08: 02" (space after the colon, seen with ML Kit on device) are parsed as times instead of ending up in the description.
- Fixed: the account form now shows the stored kurs of the currency just selected; before, switching currency left the field empty or kept the previous currency's rate, which saving then wrote as the new currency's rate.
- New: background processing with AndroidX WorkManager. `BackgroundSyncWorker` (unique periodic work every 6 h, battery-not-low, skipped while the app is on screen, 9-minute cap) runs `backgroundSyncMain` in its own headless engine: recurring sync (instances, auto-confirm with the same budget-alert/day-state listeners as the app, reminders), daily-check reschedule, widget render and the due folder backup. Never creates a database and does nothing before onboarding. The app picks up writes from other connections on resume (`PRAGMA data_version`). Recurring generation now reads and inserts in one `BEGIN IMMEDIATE` transaction and only deletes still-open instances, so the app and the job syncing at once cannot double-post. New dependency `androidx.work:work-runtime`.
- Security: the live database is encrypted with SQLCipher 4 (`sqlite3` 3.x build hook `source: sqlcipher`; random 256-bit key per device in flutter_secure_storage, namespace `finbro_database`, never logged or backed up). Plaintext databases from earlier builds are encrypted on first open into a verified copy (integrity, `user_version`, row counts) and swapped atomically; because the key store persists asynchronously, the plaintext is kept as `finbro.sqlite.plain-pending` until a later process reads the key back and opens the database, and a key lost before reaching storage is recovered from it. Backups contain a plaintext export (portable across devices) and restore re-encrypts with this device's key. A missing/rejected key shows "Data FinBro tidak dapat dibuka" with "Coba lagi" and "Mulai dengan database baru" (the unreadable file is kept as `.unreadable-<time>`). `PRAGMA busy_timeout` replaced by a Dart busy handler (`waitWhenBusy`), which also waits with the VM profiler attached. Universal APK +≈9.5 MiB.
- Fixed: the widget's headless engine looked up `widgetBackgroundMain` in `main.dart`; it is now resolved by its library URI.
- Fixed: folder backups are pasted as `<name>.partial` and renamed when complete (an interrupted copy no longer counts toward retention); leftovers are removed by the next backup. Restoring a `.finbro` with its passphrase on a device without a backup key adopts that key so automatic folder backups resume.
- Fixed: the Home (+) button sat behind the floating navbar (the `Transform.translate(-58)` lift left ~10 dp under the bar, more with a system navigation inset); the Transaksi (+) had no lift at all. Both now use `AboveNavBar`, which lifts by the bar's full height published by the shell (bar + gap + system inset); list clearance (`navBarClearance`) no longer double-counts the bar. Regression test `test/app/shell_fab_test.dart`.
- Fixed (widget): the headless widget engine had no handler for `render`, so its snapshots never reached the widget. `WidgetChannel` is now registered on that engine; while the app runs, `WidgetSync` computes on the app's own connection after writes to `accounts`, `transactions`, `exchange_rates` or `app_settings` and on every start/resume (before: ledger commits only, so opening-balance edits, kurs changes, restore and onboarding left the widget stale). Caption shows date and time (`Diperbarui 3 Okt 09:05`); hide-balance mask reads `Saldo disembunyikan` instead of `Terkunci`; the headless compute never creates the database before first launch (`Buka FinBro untuk mulai`); widget sized 4×1, opens the app on tap before the first snapshot, and has a picker description. The Kotlin `refresh` method used by the app is gone (app renders directly).
- New: encrypted folder backup is reachable from Backup & Restore ("Backup terenkripsi ke folder": folder, passphrase, harian/mingguan, keep 3/5/7/14/30, Backup sekarang, Matikan) and `.finbro` files can be restored ("Restore backup terenkripsi (.finbro)", passphrase prompt with retry; stored device key used when it matches). Container format v2: AES-256-GCM in 1 MiB chunks (STREAM nonces, header as AAD), Argon2id key; encrypt/decrypt stream file-to-file in an isolate. v1 files from development builds are rejected.
- Multi-currency completed for account-bound amounts: transaction, recurring and scan forms parse in the account's currency (an amount that cannot be represented exactly after switching account is cleared); lists, transaction detail, PDF top table and CSV (`currency` column) show native amounts; day totals, top-expense ranking, goal progress and the amount filter use rupiah via `FinanceService.idrSql`; transfer destinations are limited to same-currency accounts.
- Performance: backup validation stages every zip entry by streaming (CRC32/SHA-256 computed while writing, size limits enforced mid-stream) inside `Isolate.run`; package building also runs in an isolate. Duplicate, encrypted and non-STORE/deflate entries are rejected. Legacy byte APIs (`validate(Uint8List)`, `restoreFromBytes`, `BackupPackage.readBytes`, `ValidatedBackup.readSqlite`) removed.
- Fixed: debug "Hapus semua data" also resets exchange rates to defaults; the scanned-PDF import message no longer suggests Android can read it.
- New: multi-currency with manual exchange rates (offline). An account can be in IDR, USD, SGD, MYR, EUR, GBP, JPY, AUD, CHF, CNY or HKD; amounts are stored as integer minor units (IDR/JPY units, others cents). Every cross-account figure — Total Balance, Available to Spend, emergency coverage, savings rate, budget actuals, reports — is converted to rupiah with the manual kurs (`ROUND(minor × rate ÷ 10^decimals)`); per-account screens keep the native amount and show the ≈Rp conversion. Kurs editor in Pengaturan → Kurs Mata Uang (`/settings/rates`), default rates seeded (USD 16250 …). Transfers between different currencies are rejected with a clear message (move money via two transactions). Formatted/entered amounts use `formatMoney`/`parseMoney` with id_ID grouping; the IDR path is unchanged.
- New: Android home-screen widget (4×1) showing the Total Balance and an update caption. Masking: while an app-lock PIN is set the widget always shows `••••••` + `Terkunci` (disable the lock to see amounts); the in-app hide-balance toggle masks as well. The amount is computed in Dart (`FinanceService.totalBalance`); see the widget fix above for the current refresh flow.
- New: PDF statement import completes the bank-mutation importer. Mutasi bank PDF with a text layer (BCA/Mandiri layout) is parsed by the statement line parser (`parseStatementLines`) and lands in the `/import` review flow with duplicate detection. Encrypted PDFs ask for a password (up to 3 attempts); scanned-only PDFs were rejected at first (OCR added later, see top).
- Database schema v5: new `exchange_rates` table (`code` TEXT PRIMARY KEY, `rate_to_idr` REAL CHECK(> 0), `updated_at`) storing manual rupiah-per-unit rates for multi-currency accounts, plus the `Currency` enum (IDR, USD, SGD, MYR, EUR, GBP, JPY, AUD, CHF, CNY, HKD). The v5 migration creates the table and seeds default rates (USD 16250, EUR 17250, …); fresh installs seed the same rows in `seedDefaults`. Migration tested (`test/core/schema_migration_test.dart`, frozen `drift_schemas/drift_schema_v5.json`).
- Performance/reliability: backup and restore are now fully file-backed and streaming. Building a backup writes the zip entry-by-entry to disk (`_StreamingZipWriter`, stored entries with streamed CRCs) instead of accumulating it in memory; restore validation (`BackupService.validateFile`) stages each zip entry to a temp file and verifies the CRC32, safe entry names, per-entry size and total size, and the manifest's SHA-256 checksums for the database and every attachment. Staged files and temp archives are disposed on every path (cancel, failure, success). Memory no longer scales with backup size (limits unchanged: 512 MB zip / 256 MB per entry / 1 GB unpacked, now enforced as file sizes).
- Security: PIN hash is now bound to the device. An HMAC-SHA256 key that never leaves Android Keystore (`PinVerifierChannel`, alias `finbro.app_lock.pin_binding.v1`) signs hash+salt; verification is constant-time, and Keystore failures are explicit (`PinIntegrityException`) — the app never silently downgrades to a database-only verifier. Hashes stored by older versions migrate automatically after the first correct PIN. Covered by `pin_hash_test.dart`.
- Security: encrypted backups to a user-chosen folder (passphrase-derived key) — domain layer; UI and `.finbro` restore landed later (see top).
- New dependencies: `convert` (streaming digest sink), `pdfrx` (PDF statement text layer), `pdf` (report export), `cryptography` (AES-GCM/Argon2id), `saf_util`/`saf_stream` (folder access), `flutter_secure_storage` (backup key).
- Security: attachment files are now checksummed. Backups store a SHA-256 per attachment entry (`attachmentChecksums` in the manifest) and restore rejects a backup whose unpacked attachment does not match; the new `attachments.file_sha256` column (schema v4, migration tested) lets the integrity check flag attachment files modified after restore (report field `checksumMismatches`). Older backups without checksums still restore.
- New: bank statement CSV import (Lainnya → Impor Mutasi Bank). Detects BCA, Mandiri, BNI, BRI, Jago, SeaBank and blu exports; manual column mapping when detection is unsure; per-row category and include/exclude; duplicate warning against existing transactions; imported rows post as confirmed with source `statement_import`.

## Release policy
- Version lives in `pubspec.yaml` (`version: x.y.z+build`). Every Play upload needs a higher `+build`; keep `appVersion` in `about_screen.dart` in sync.
- GitHub releases: tag `v<x.y.z>` and attach the signed universal APK as `FinBro-<x.y.z>.apk` (`gh release create`). The AAB is for Play Console only and is not attached.
- `drift_schemas/drift_schema_v1.json` is the frozen v1 baseline. When bumping the schema run `dart run drift_dev schema dump lib/core/database/app_database.dart drift_schemas/` and generate migration test helpers from it (`drift_dev schema generate`).
- Any Drift table change: bump `AppDatabase.currentSchemaVersion`, add a stepwise block in `onUpgrade`, and add a migration test that opens a database created at the previous version. Backups from older schemas must restore through the migration; backups from newer schemas are rejected (`backup_service.dart`). Current: schema 5 (3 Okt 2026: `exchange_rates`).
- minSdk 24 (Android 7.0); targetSdk follows Flutter's default (36 on Flutter 3.47.2). Raise minSdk only when a dependency requires it.
